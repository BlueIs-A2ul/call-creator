# callCreator 用户手册

把 QQ 音乐 / 网易云的歌曲链接（或者现成的歌词文本、表格）变成一张排练时能用的「歌词 + call 词」双列表，最后导出成 xlsx 或 PDF 打印。

- 本地单用户工具，数据存在你自己机器的 `data/` 目录里，不上传、不需要账号。
- 歌词版权归原平台与权利人所有，本工具只做本地个人编排，不提供公开分发。

## 1. 启动

```bash
npm install
npm run dev
```

- 打开 **http://localhost:5173**（开发模式，改代码会热更新）
- 后端在 http://127.0.0.1:8787，前端会自动把 `/api` 请求代理过去

只想用、不改代码的话：

```bash
npm run build
npm start
```

然后打开 **http://127.0.0.1:8787**。

## 2. 快速上手

一份 call 表的最小流程：

1. **建项目**：在首页粘贴歌曲链接 → 点「生成」，表格里出现这首歌的每一句歌词。
2. **补间奏行**：点工具栏「识别间奏」→ 勾选要插的位置 →「插入间奏行」（从链接建的项目会自动插一次）。
3. **填 call**：点某行的 Call 格 →「＋ 添加 call」→ 手写，或点「从词库选择」挑一条。
4. **一个长 call 跨多行**：点行号选中起止几行 → 上方「应用一个 call」→ 从词库选词条，自动按行切段。
5. **导出**：工具栏「导出」→ 勾选需要的列 → 「导出 xlsx」，或「打印 / 另存 PDF」。

改哪都会**自动保存**，右上角显示「已保存」就说明落地了。

## 3. 新建项目

首页叫 **Call Sheet**，有三种建法，都在同一个页面上：

### 3.1 粘贴歌曲链接（推荐）

1. 在输入框粘贴网易云或 QQ 音乐的链接，例如
   - `https://music.163.com/song?id=2733002471`
   - `https://i.y.qq.com/v8/playsong.html?songid=634196637#webchat_redirect`
2. 点「生成」，抓取成功后直接进入表格。

注意事项：

- 只认这两家的域名：网易云的 `music.163.com`（含 `y.music.163.com` 等子域）和 `163cn.tv` 短链；QQ 音乐的 `y.qq.com`（含 `i.y.qq.com`、`c6.y.qq.com`、`u.y.qq.com` 等子域）。其它站点的链接会报「不支持的域名」。
- 如果链接里可能对应多首歌，页面会列出「找到多首歌，请选择：」，点其中一首继续。
- 抓取失败时页面会自动切到粘贴模式，也可以手动点「抓取失败？粘贴歌词」提前切换。

### 3.2 粘贴歌词

点「抓取失败？粘贴歌词」→ 把 LRC 或纯文本歌词贴进大文本框 → 「生成」。

- LRC（带 `[mm:ss.xx]` 时间戳）会保留时间，能用来识别间奏。
- 纯文本没有时间戳，标题是「未命名」，也**无法**识别间奏。

### 3.3 导入表格（.xlsx）

点「导入表格（.xlsx）」，选一个 xlsx 文件。程序**只读第一个工作表的 A 列**，非空单元格逐行变成歌词行。

- 读到的标题/歌手都是空的，项目名会是「未命名」，进去后可以直接改标题。
- 没有时间戳，所以「识别间奏」会提示无法识别。

### 3.4 打开已保存的项目

首页下方「已保存」列出所有项目（标题、歌手、行数）。点卡片打开；点右侧「删除」会先确认，**删除不可撤销**。

> 刚打开首页时如果显示「读取中…」说明在拉列表；读取失败会显示原因和「重试」按钮。

## 4. 编辑歌词行

进入表格后是「# / 歌词 / Call」三列，每行一个歌词句：

| 想做的事 | 怎么做 |
| --- | --- |
| 改歌词文本 | 直接点歌词格改（多行会自动撑高） |
| 新增一行 | 鼠标移到行号，右侧出现「＋」（在下方插入空白行），插入后光标自动落进新行 |
| 删除一行歌词 | 行号右侧的「×」。删完底部会弹提示，5 秒内可以点「撤销」 |
| 调顺序 | 拖拽整行到目标位置 |
| 改标题 | 左上角标题框直接改 |

空白行是有用的：它是放间奏 call 的地方，歌词格会显示「（空白行，可填写间奏 call）」。

## 5. 填一个单行 call

点 Call 格里「＋ 添加 call」打开「编辑 Call」弹层，填三样东西：

- **名称**：例如「首推call」，显示在格子上方的小标签里。
- **正文**：真正的 call 词。可以直接手写，也可以点「从词库选择」挑词条（挑中的内容会**追加**到现有正文后面，不会覆盖）。
- **标签（逗号分隔）**：用来给导出时的「标签」列，也可以只是自己备注。

改完点「保存」。注意：**点「取消」、点遮罩、按 Esc 都会丢弃这次改动**，草稿是在弹层里的（只有占位符的「全表默认」例外，见 [9.1](#91-在-call-里填值)）。

弹层左下角还有两个操作：

- 「清空这个 call」：删掉这一行的 call，歌词行保留。
- 「拆出这一行」：只在跨行 call 里出现，把它从块里摘出来变成独立的 call。

## 6. 一个 call 覆盖多行

call 词不一定只出现在间奏，歌中间也常有一长段要连喊几句歌词，这时候一个 call 要铺在连续几行上。

### 6.1 操作步骤

1. 点行号选中第一行，再 **Shift + 点**最后一行（Ctrl / ⌘ + 点可以挑不连续的行）。
2. 表格上方出现选中条：`已选 N 行 [应用一个 call] [清除 call（N）] [取消选择]`。
3. 点「应用一个 call」，从词库挑词条 →「插入」。

选中的行会立刻被填上 call：

- 每行右上角出现段号 `1/4`、`2/4`…，块首行显示词条名称，续行不重复显示名称。
- 段号顺序就是行的先后顺序：拖动行或插入行之后，段号会跟着自动重算。

### 6.2 词条是怎么切成几段的

1. 只取词条里的**「罗马字」那一段**（排练时喊的就是它）；词条里写了「原文：」/「罗马字：」这种分段标题时，原文那段会被丢掉。如果词条只标了原文、没有罗马字段，就退回用原文那段；完全没有分段标题时，整段每行算一句。
2. 句数 = 行数 → 一句一行。
3. 句数 > 行数 → 尽量均分：6 句分给 4 行是 `2/2/1/1`，多出来的句子在同一格里换行。
4. 句数 < 行数 → 前面的行一句一个，剩下的行显示「（这一段留空）」，留给你手补。

### 6.3 之后再微调

- 点块里任意一格 →「编辑 Call」：**改名称或标签会同步整块**，改正文只影响这一行（正文和占位符永远是每行自己的）。
- 想拆开：「拆出这一行」。拆中间那行会让块断成前后两块，各自从 `1/N` 重新编号。
- 想把整块挪走：直接拖拽行，块跟着行走（相邻性由行位置决定）。

## 7. 清空或删除 call

歌词行和 call 是两件事：删 call 不会删歌词，删歌词才会连 call 一起删。

| 想做的事 | 操作 |
| --- | --- |
| 清掉整块 call | 选中这几行 → 上方「清除 call（4）」，一次清完；括号里的数字是选中行里真的有 call 的行数 |
| 只清某一行 | 鼠标移到那行 Call 格，右上角出现「清除」，点它 |
| 在编辑器里清 | 打开「编辑 Call」→ 左下角「清空这个 call」 |
| 删整行歌词 | 行号右侧的「×」（这个会连 call 一起删） |

清完之后底部会弹「已清除 N 行的 call」「已删除 1 行歌词」之类的提示，5 秒内点「撤销」可以还原。清掉块中间的一行时，块会自动断成两块，同样可以撤销。

> 别拿「×」当清 call 用——它是删歌词行。

## 8. 间奏

### 8.1 行号上的间奏徽标

当相邻两句歌词的起始时间相差 ≥ 6 秒时，第一句的行号下方会显示 `间奏 mm:ss–mm:ss`。这只是提示，不会改数据。

### 8.2 识别间奏并插入空白行

工具栏「识别间奏」：

1. 「最小间隔（秒）」默认 10，可调 3–60：间隔越大，被判定成间奏的位置越少。
2. 下方列出所有候选（时间区间 + 约多少秒），逐个勾选要保留的。
3. 点「插入间奏行」→ 在每个候选的**前一句歌词后面**插入一行空白行，直接用「＋ 添加 call」写间奏 call。

说明：

- 从链接新建项目时会自动按默认 10 秒插一次；之后再点「识别间奏」不会重复插（已经插过的位置不再出现）。
- 纯文本粘贴或 xlsx 导入的歌词没有时间戳，弹层会直接提示无法识别。

### 8.3 为什么间奏起点偏早

LRC 只有每句的**句首**时间，没有句尾；间奏要等上一句唱完才开始，所以自动算出的起点会比真实间奏早一点（终点取下一句的句首，基本准确）。首页顶部有一段「关于间奏时间」的说明，原因同上。

## 9. 占位符 OOO 与 XXX

call 词里常写 `OOO`、`XXX` 或 `【名字】` 当占位符，排练前再填具体人名/口号。本工具认这三种写法。

### 9.1 在 Call 里填值

「编辑 Call」的正文里一旦出现占位符，弹层下方会出现「占位符」区，每个占位符两个输入框：

- **左框「全表默认」**：写进整个项目的默认值，所有用到这个占位符的 call 都跟着变，可撤销、会自动保存。注意它**改完立刻生效**，不受弹层「保存 / 取消」影响。
- **右框「仅这个 call」**：只替换当前这一行，留空就用默认值。它跟着「保存」走，取消就丢弃。

表格里显示的是**替换后**的结果（没填值就原样显示 `OOO`）。

### 9.2 导出时才决定要不要替换

「导出」弹层里「应用占位符替换」默认**不勾**——也就是导出的 xlsx 里保留 `OOO` 原文。勾上才会把默认值/覆盖值写进去。

## 10. 词库

工具栏「词库」打开右侧抽屉，写 call 时点「从词库选择」打开的是同一个抽屉，只是每张卡片多一个「插入」按钮。

- **搜索**：匹配名称、标签、正文，名称命中最优先；输入后自动搜（约 250ms 延迟）。
- **标签**：点标签筛选，可多选（命中任意一个就算）。
- **分页**：一次先显示 30 条，底部「显示更多（还有 N 条）」继续加载。
- **新建词条**：点「新建词条」填名称（必填）、标签（逗号或空格分隔）、正文（必填）→「保存到词库」。自建词条存在 `data/library.user.json`，会出现在搜索结果里。
- **删除自建词条**：自建词条卡片上有「删除」（内置词条没有这个按钮）。
- **刷新**：点「刷新」才会去请求远端最新词库。日常启动和搜索**完全不联网**，读的是仓库里的本地快照 `library/library.json`。
- 如果看到「词库缓存可能不是最新」，说明上次刷新失败、正在用旧数据。

想把远端最新数据固化成团队共用的快照，在终端里跑：

```bash
npm run library:sync   # 写回 library/library.json，提交后其他机器也用这份
```

## 11. 保存撤销与关闭页面

### 11.1 自动保存

- 停止输入约 0.8 秒后自动保存，右上角状态从「保存中…」变成「已保存」。
- 保存失败会自动再试 2 次（间隔 3 秒、6 秒），仍失败则显示红色「保存失败」+「重试」按钮。把鼠标停在这行字上能看到具体原因。
- 想立刻保存：按 `Ctrl/⌘ + S`，或点「重试」。
- 关标签页、切到后台时还会兜底补发一次保存，最后几秒的改动一般不会丢；只有在**保存已经失败**的状态下关页面，浏览器才会弹确认框。

### 11.2 撤销 / 重做

- `Ctrl/⌘ + Z` 撤销，`Ctrl/⌘ + Shift + Z` 或 `Ctrl/⌘ + Y` 重做，工具栏也有按钮（没历史时按钮是灰的）。
- 最多保留 100 步；在同一个输入框里连着打字会被合并成一条历史，不会一步一个字。
- 在弹层（编辑 Call、导出、词库…）的输入框里，`Ctrl + Z` 是浏览器自己撤销输入，不会动整个项目的历史。
- 底部提示条上的「撤销」（删行、清 call 之后）用的是同一套历史。

### 11.3 回项目列表

左上角「← 列表」。如果还有改动没存完，会先问一句「还有改动没存完，确定返回列表？」。

## 12. 导出 xlsx 与打印 PDF

点工具栏「导出」：

| 选项 | 默认 | 作用 |
| --- | --- | --- |
| 空白行合并到上一行 | 关 | 把空白行并进上一行，Call 格里多一行「（间奏）」；关着的话空白行是独立一行、单独占一个序号 |
| 包含标签列 | 关 | 多加一列「标签」，同一行的多个标签用 ` / ` 连接 |
| 包含备注列 | 关 | 多加一列「备注」 |
| 包含时间列 | 关 | 多加一列「时间」（`mm:ss.SS`），只有抓取来的歌词有时间 |
| 应用占位符替换 | 关 | 勾上才把 `OOO` 等替换成实际填写的内容 |

- 列固定为「序号 / 歌词 / Call（+ 可选列）」，表头加粗并冻结在顶部。
- **跨行的 call 在 xlsx 里是纵向合并的一格**：名称写一次，下面按行把各段接起来，行高按内容估算。弹层里会提示「有 N 个跨行的 call…」。标签/备注只写块首那一行。
- 文件名是 `<项目标题>-call-sheet.xlsx`；导出前会先把当前项目存一遍，导出的就是屏幕上看到的内容。
- 「打印 / 另存 PDF」调用浏览器打印。打印版**不合并**：每行显示自己那一段，工具栏、选择条等交互元素会隐藏，A4 纵向。在打印对话框里选「另存为 PDF」即可。

### 12.1 重抓歌词

歌词抓错了或者换了版本，点工具栏「重抓歌词」：

1. 填（或保留）歌曲链接 →「抓取」。
2. 弹层会告诉你「新歌词 N 行，找不到归属的旧 call M 条」。匹配是按歌词文本逐行对上的（忽略首尾和多余空格）。
3. 对不上的旧 call 有两个选择：「保留为空白行」（挂在新歌词后面，之后手动挪位置）或「丢弃旧 call」（不要了）。

注意：重抓后行的时间戳会被刷新，跨行 call 的块可能因为行序变化而被拆散。

## 14. 出错了怎么办

界面上的报错都是人话，同时服务端终端会打一行 `[lyrics] ...` 或 `[server] ...`——先看终端。

| 报错 | 含义 | 怎么办 |
| --- | --- | --- |
| 不支持的域名：… | 链接不是歌曲详情页，或域名不在白名单 | 换成歌曲详情页链接 |
| 连不上音乐平台（NETWORK） | DNS 失败、连接被重置、超时（10 秒） | 服务端已自动重试一次；仍失败就稍后再试，或改用粘贴歌词 |
| 没有可用歌词（NO_LYRICS） | 歌存在但没歌词，或 id 查不到 | 换版本，或粘贴歌词 |
| 平台返回的不是 JSON | 一般是被风控拦了 | 稍后再试 |
| 服务器内部错误：… | 程序自身没料到的异常 | 看终端堆栈，把那一行贴出来就能定位 |
| 保存失败 | 后端没起来或磁盘写不进去 | 确认 `npm run dev` / `npm start` 还在跑，再点「重试」（改动还在页面上） |
| 词库持续报错 | 本地快照丢失且刷新失败 | 跑 `npm run library:sync` 重新生成 `library/library.json` |

## 15. 数据放在哪

| 路径 | 内容 |
| --- | --- |
| `data/projects/*.json` | 每个项目一个文件（歌词行、call、占位符默认值、版本号） |
| `data/library.user.json` | 自建词条 |
| `data/library.hidden.json` | 隐藏的内置词条 |
| `data/cache/library.json` | 点「刷新」后的运行时缓存（可删，删了回落到本地快照） |
| `library/library.json` | 仓库里的词库快照（提交到 git，团队共用） |

备份就是拷走 `data/` 目录。`data/` 不进 git，换机器需要自己搬。

## 16. 已知限制

- 词库切段只取「罗马字」那一段；词条里没有分段标题时按行切，切得不合适就在编辑器里手动改。
- 同时选中不连续的行，会被切成多个独立的块（每段连续行一块），段号各自从 `1/N` 开始。
- xlsx 只合并 Call 列；标签/备注/时间列不合并（内容只写在块首行）。
- 表格里 `OOO` 这类占位符显示的是替换后的值（没填就原样显示），导出是否替换由「应用占位符替换」决定。
- 间奏起点是近似值（原因见 [8.3](#83-为什么间奏起点偏早)）。
- 删除项目不可撤销；删除歌词行、清 call 可以用撤销救回来。
- 抓取只支持网易云与 QQ 音乐；QQ 的关键词搜索在当前网络下不稳定，建议直接粘贴歌曲链接。
